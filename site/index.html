Hyperbolic Gateway

A web browser your AI can drive. It runs a real, visible Chromium on your own machine and speaks MCP, so it drops into whatever agent runner and whichever model you already use — local or remote. No cloud account, no API key, no seat pricing, and no telemetry leaving your computer.

What it is

A real browser, not a headless script

A visible Chromium window with DevTools-grade control. It opens pages, reads them, clicks, types, fills forms, downloads files, and keeps working while you use your own machine.

59 tools, tier-graded

Reading is observe with inline [#id] marks — no screenshot tax. Interaction is one act. Tiers (prefer / fallback / use deliberately) tell the agent what to reach for first.

Memory that stays on your disk

LanceDB-backed semantic recall of pages you've visited, plus a local action ledger of what each action actually did. Nothing is uploaded, ever.

How it differs, honestly

Property Hyperbolic Gateway Browser clouds / hosted agents
Where it runs Your desktop, your browser session Their infrastructure, their IPs
Accounts & keys None Account, API key, per-seat or per-minute billing
Data Stays local (pages, memory, logs) Transits and may persist on their side
Model choice Any MCP-capable runner — local or remote Usually tied to the vendor's models
Is it a bot? Looks like a person: real pointer, humanlike typing, consent handled Often a flagged datacenter browser
Scale One operator, one machine Thousands of parallel sessions
Rough edges Experimental, one developer Supported product

It is not trying to beat a browser cloud at scale. It is trying to be the honest local option: the browser you already have, driven by the model you already chose.

Install

1. Run the app

git clone https://github.com/hyperbolictonic/hyperbolic-gateway.git
cd hyperbolic-gateway
pnpm install
pnpm dev          # or: pnpm run build && pnpm start

2. Point your MCP client at it

Add this to claude_desktop_config.json, mcp_config.json, or your runner's equivalent: 

{
  "mcpServers": {
    "hb-browser": {
      "command": "node",
      "args": ["C:/path/to/hyperbolic-gateway/bin/mcp-server.cjs"],
      "env": { "HB_BRIDGE_URL": "http://127.0.0.1:4111" }
    }
  }
}

The Cyberdeck app must be running in the background — the MCP stdio bridge talks to it on http://127.0.0.1:4111. Windows x64 is the tested target.

Design choices you can hold it to

  • Humanlike or nothing. Input goes through real pointer and keyboard events with Bézier paths, tremor and minimum-jerk velocity. The simulator flags anything that isn't isTrusted.
  • Focus-independent. Clicks and typing land while your editor owns the foreground, and occluded windows keep hydrating — long harvests run behind your other apps.
  • Honest about limits. Detached reads are gated, evaluate_javascript is "use deliberately" rather than banned, and failures are machine-coded (STALE_REF, TIMEOUT, NO_TARGET) instead of vibes.
  • Advisory, not silent. Tools recommend a course of action and return evidence; they don't quietly mutate behind the agent's back.
  • No telemetry. There is no analytics endpoint in this project. The only network traffic is the web you asked it to visit.
